The Malware Severity Score (MSS) puts the before and after values on the same normalized 0–1 scale, so the reduction can be read directly for each sample and compared across samples. The definitions of IS, RA and F are on the [CCEA page](/methodology/ccea/).

## Comparison with a Greedy Baseline

CCEA is compared with a **greedy baseline** run on exactly the same inputs. Both methods use:

- the same candidate pools P<sub>k</sub> from the candidate dataset D (17 samples, 2,823 rows);
- the same RS source (the same Reduced_Severity mode and RS table);
- the same fitness definition.

Because the inputs are identical, any difference in MSS<sub>after</sub> or fitness comes from the search itself. Each sample therefore yields a paired result: one value for CCEA and one for the greedy baseline.

---

## Statistical Validation

The paired per-sample results are tested in two steps:

1. **Shapiro–Wilk test** on the paired differences, to check whether they are normally distributed.
2. **Wilcoxon signed-rank test** at significance level **α = 0.05**, a non-parametric paired test that does not assume normality. It tests whether CCEA's results differ systematically from the greedy baseline's across the samples.

The same paired test is applied to MSS<sub>before</sub> against MSS<sub>after</sub> to test whether the recommended defenses reduce the Malware Severity Score across samples.

| Test | Question it answers | Decision rule |
|:---|:---|:---|
| **Shapiro–Wilk** | Are the paired differences normally distributed? | Normality rejected if p < 0.05 |
| **Wilcoxon signed-rank** | Do CCEA and greedy (or before and after) differ systematically? | Difference significant if p < 0.05 |

## Residual-Severity Evaluation

The RS estimates are evaluated against a reference dataset of attack–defense pairs whose residual severity is labelled independently of the model. Each record keeps the signature, its impact score A<sub>k</sub>, the candidate defense, the input evidence, the reference RS, the predicted RS and the evaluation status.

<DataTable 
  headers={["Metric", "What it measures", "Why it is used"]}
  caption="Table 4.2: Metrics for residual-severity estimates."
>
  <tr>
    <td><strong>Quadratic Weighted Kappa (QWK)</strong></td>
    <td>Agreement between predicted and reference RS on an ordered scale, penalizing larger disagreements more.</td>
    <td>RS is ordinal; being off by 5 is worse than being off by 1.</td>
  </tr>
  <tr>
    <td><strong>Normalized MAE (MAE / 10)</strong></td>
    <td>Average absolute error as a fraction of the 0–10 RS scale.</td>
    <td>Expresses error size in the units the fitness uses.</td>
  </tr>
  <tr>
    <td><strong>Exact-match accuracy</strong></td>
    <td>Share of predictions equal to the reference RS.</td>
    <td>The strictest view of agreement.</td>
  </tr>
  <tr>
    <td><strong>Tolerance accuracy (±1)</strong></td>
    <td>Share of predictions within 1 of the reference RS.</td>
    <td>Separates near-misses from real errors.</td>
  </tr>
  <tr>
    <td><strong>Macro-averaged F1</strong></td>
    <td>Classification quality of the FULL / PARTIAL / NONE mitigation labels.</td>
    <td>Checks the categorical judgment class by class.</td>
  </tr>
</DataTable>

Each evaluation run reports the number of eligible cases, skipped records, invalid predictions, failed requests and successful predictions, together with the model version, prompt version and inference settings. Reference labels are assigned independently of the model, and examples used while developing the prompt are kept out of the evaluation set.
